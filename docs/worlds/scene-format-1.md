This is the language of a scene — a place of a living, animated world, with its mood: what you write when you paint a scene or change one (as the person you work for describes the world or a place in it, or as a game played on the world needs). A scene is the files of its folder, `scenes/<folder>/`: `scene.json` — the spec below without its code — and its code, each piece in a file of its own (`worlds/README.md`: The repository); where the schema below has code in a field, that field is its file. Everything in the scene — sky, sun, moon, stars, clouds, land, water, trees, buildings, people, weather, glints — you paint yourself, with code, for this scene.

Schema:
{
  "title": string,                 // short name of the place, in English (a scene is written in English; its translations beside it — Translations, below)
  "caption": string,               // one quiet line shown over the scene, in English
  "horizon": 0..1,                 // eye level on screen, from the top (the viewer's eyes are 1.7 m above the ground)
  "objects": [ element, ... ],     // everything in the scene (below)
  "camera": { "mode": "picture"|"walk"|"panorama"|"overhead"|"around"|"roam"|"platform", "hero": element id, "jump": metres, "height": metres, "look": -0.3..0.45, "span": [metres, metres], "turn": degrees, "area": [metres, metres, metres, metres], "follow": [element id, ...] },  // optional, below
  "light": { "tint": color, "tintStrength": 0..0.5, "vignette": 0..1, "grain": 0..1,
             "haze": 0..1,                 // air between the viewer and far things: 0 crystal clear … 1 thick fog
             "hazeColor": color,           // the colour far things fade toward
             "hazeGlow": 0..,              // the haze lit by the lights (lights, e.light): warm and bright round a lamp, a fire, a window; 1 as fog scatters it
             "brightness": 0..2, "saturation": 0..2,  // of the whole picture (default 1)
             "ambient": 0..1, "ambientColor": color,  // a lit scene (below)
             "bounce": 0..1,               // a lit scene: the light that lit things give back, filling what is darker than its surroundings (0.5; 0: none)
             "looks": { key: { light fields } } },    // the light the state turns it to: night, dawn (below)
  "lights": [ light, ... ],        // where light comes from: a lamp, a forge, the moon (optional, below)
  "captions": [ { "text": string, "at": seconds, "for": seconds } ], // lines appearing over the scene in time (optional; without "for" a line stays)
  "widgets": [ widget, ... ],      // the scene's own bits of interface over the picture (optional, below)
  "state": { key: value, ... },    // the scene's state — where its values start (optional, below)
  "states": { key: { "range": [min, max] | "values": [value, ...] | "type": "number"|"boolean"|"string", "smooth": boolean, "means": string }, ... }, // what each value is (optional, below)
  "relief": string,                // the land's shape, JS (optional, below)
  "script": string,                // the scene's own mechanics, JS (optional, below)
  "lib": string,                   // code the scene's elements and scripts share (optional, below)
  "modules": [string],             // the world's modules this scene uses, by name (optional, below)
  "notes": string,                 // yours, for whoever works on this scene next — you again, another artist, an assistant (optional, below)
  "music": {                       // the scene's soundtrack, generated live (instrumental, no vocals) from these descriptions mixed by weight
    "prompts": [ { "text": string, "weight": 0..2 } ],  // many (15–25) distinct, vivid descriptions in English — genre, instruments and how they're played, mood, texture, tempo feel, era, place; weight the few that fit this scene best, leave most at 0: the author tries them with sliders
    "bpm": 60..200, "density": 0..1, "brightness": 0..1,  // optional
    "scale": "C_MAJOR_A_MINOR" }  // optional: the key — a major and its relative minor, one of C_MAJOR_A_MINOR, D_FLAT_MAJOR_B_FLAT_MINOR, D_MAJOR_B_MINOR, E_FLAT_MAJOR_C_MINOR, E_MAJOR_D_FLAT_MINOR, F_MAJOR_D_MINOR, G_FLAT_MAJOR_E_FLAT_MINOR, G_MAJOR_E_MINOR, A_FLAT_MAJOR_F_MINOR, A_MAJOR_G_FLAT_MINOR, B_FLAT_MAJOR_G_MINOR, B_MAJOR_A_FLAT_MINOR; one for the whole world (every scene of it, and its game's mini-games: style({key}))
}
color = "#rrggbb".

The frame is always landscape — 4:3 to 21:9 — and its height is the measure. The scene is laid out on a 16:9 stage as tall as the frame: a 16:9 screen shows all of it, a 4:3 one only its middle (x 0.125..0.875), a 21:9 one also 0.16 beyond either side. Keep what matters within x 0.125..0.875; let everything else run on past the edges. The world is 3D: the viewer stands at the start with eyes on the "horizon" line and can walk forward/back, step sideways and look up/down; near things move more than far ones. Far things are hazed toward hazeColor; walking closer clears it.
"camera" — how the viewer moves through the scene (default walk):
- "picture" — a still picture: the view breathes and leans a little toward the pointer or the phone's tilt, near things shifting against far ones: one composed picture (a box, a stage, a room seen from its open side).
- "walk" — at eye height, within "area" [left, right, back, front] metres of the start, else as far as the things standing in it. The start is as far back as the viewer can be and there they can't step aside — the foreground you paint holds the frame; coming closer they may. "follow": elements the camera keeps in view as the viewer walks (characters who walk and run); a film's camera_target (below) frames instead.
- "panorama" — a long place passed along sideways (an alley, a street, a shore, a train window): as far as "span" [left, right] metres (else the things within 40 m); lay it out with "across".
- "overhead" — raised "height" metres (8), looking down "look" screen heights (0.25): a table, a board game, a town from a rooftop; what stands stays upright like figures on a board.
- "around" — one spot, the head turned all round (or "turn" degrees either way) and up and down: a clearing by a fire, a tower's top. "roam" — walking about a place, looking anywhere, as in a room ("area", else among the things around). Place elements by "bearing" (degrees from straight ahead, right +, 180 behind) and "distance"; the sky is the full circle: x 0..e.aspect all round, straight ahead at e.aspect/2 — paint it so the ends meet (sin, cos of x with whole periods). The viewer's own floor is a plane with "distance" 0.01.

An element:
  { "id": string,                       // short stable id ("pier", "moon"); when editing a scene keep each element's id, new elements get new ones
    "name": string (in English),
    "sky": true,                        // an element of the sky (sky, sun, moon, stars, clouds): infinitely far, never moves when walking
    "x": 0..1,                          // otherwise: where its anchor is, across the stage (seen from the start)
    "across": metres,                   // ... or instead: metres to the right of the start's line of sight (left negative) — for a place longer than the view
    "bearing": degrees,                 // ... or, looking around: which way from the start (with "distance")
    "facing": degrees,                  // turned its own way (a wall, a door, a house's side), in any camera, about its anchor: where its face looks (180 toward the start; 90 to the right — its +x then runs away from the start)
    "tilt": degrees,                    // leaned back from upright about its anchor's line: a lid thrown open, a board leaning (−90…90; what slopes for good is a plane)
    "y": 0..1  OR  "distance": metres,  // where it touches the ground on screen, or how far away it is
    "elevation": metres,                // anchor height above the ground, default 0
    "height": metres,                   // its real height: the box and the code are in metres at the size it gives
    "box": [left, top, right, bottom],  // metres around the anchor that the painting fits in; default [-0.8h, -1.1h, 0.8h, 0.15h] — paint past it is cut off straight (the engine says so)
    "color": color,                     // default fill/stroke
    "code": string,                     // JS function body painting it (below)
    "period": seconds,                  // e.phase runs 0..1 over this period
    "sway": degrees, "bob": metres,     // gentle motion the engine adds to the whole element
    "flicker": 0..1,                    // how much its lights flicker
    "reflect": boolean,                 // a faint copy below it, fading down (in water: about the surface under it; a sky element: about the horizon); over a reflecting plane not needed
    "glass": true | { "strength": 0..1 (0.25), "blur": (0.03) }, // a pane of glass: the room mirrored in it (below)
    "place": { "across"|"distance"|"elevation"|"x"|"facing"|"tilt": state key, ... }, // it moves (or turns) through the world: where the state says (below)
    "on": string,                       // it stands on that element and goes and turns with it; its place and facing are in that one's own turn (below)
    "after": [string],                  // elements whose painting its code reads (another figure's hand, through a module): painted first each frame
    "behind": [string], "inFront": [string], // drawn behind / in front of these, whatever the distances (below)
    "clip": { "inside" | "outside": [string] }, // seen only within / out of what these paint (below)
    "unseen": true,                     // not shown: an anchor others stand on, a point the camera looks at (no code needed), a shape others are clipped by
    "insert": state key, "iris": [x, y, rx, ry], // a shot of its own over the scene (below)
    "shadow": true | { "light": id, "onto": ["ground" | element id, ...], "strength": 0..1, "soft": metres }, // (below)
    "glows": true,                      // a lit scene's light doesn't darken it: a lamp, a fire, a lit window
    "inside": true,                     // it is in a room: lit by the light that comes in (light "inside", below)
    "translucent": 0..1,                // something thin — a sail, leaves, paper, a curtain: how much of the light behind it comes through (below)
    "redraw": [state key, ...] | { key: step }, // only these keys repaint it, once moved by `step` (a big plane on a key moving smoothly), whatever else it reads
    "script": string }                  // this element's own mechanics, JS (below)
  The code is the body of function (g, e): g is a CanvasRenderingContext2D. For a normal element it is in METRES, origin at the anchor, x to the right, y DOWN — so up is negative (a 6 m house spans y −6…0). For a sky element it is in SCREEN HEIGHTS from the stage's top-left corner: x 0..e.aspect is the stage, y 0..1 (paint x from −0.3 to e.aspect + 0.3 — wide screens see past the stage — and y from −0.35 to 1.25 — the viewer can look up and down). Fill and stroke with paths, arcs, bezier curves, gradients, g.globalAlpha, composite modes, 'evenodd' fills for holes. No DOM, no network, no timers — just drawing, and no memory: it paints what is now; what goes on from frame to frame is kept by beforeFrame and only read here (Painting and beforeFrame, below). e gives:
  - e.t — seconds (the real clock, in step with the state's moves); e.phase — 0..1 over "period"; code reading e.t or e.phase (itself or through a module) is repainted every frame, code reading only e.state when a key it read changes (a clock's `second` repaints the clock alone); e.id; e.rnd() — seeded random 0..1, the same every time; e.px — one screen pixel in the element's units;
  - e.state — the scene's values (below); e.was(key, secondsAgo), e.speed(key) (per second) — what lags behind reads them: a coat's tail, hair, a head following the body; e.cut — when the last cut was (scene.cut, or the start), by e.t's clock: what beforeFrame keeps (springs, cloth, hair) starts afresh after it;
  - e.light(x, y, radius, color, strength, name?) — a glow the engine draws and animates, and a source of light reaching twice its radius (its id the element's, or "id#name"); e.lights(x, y) — the light falling on that point, strongest first: [{ id, color, strength, x, y (toward it on the painting, y down), z (+ from the viewer's side; − from behind: an edge of light), dir (degrees on screen: 0 right, 90 down), distance (m; null from far off) }] — a figure takes its rim from the right side (repainted as the light moves); e.ambient — the ambient light now (1 unlit; "inside": the share that comes in);
  - e.at(x, y) — where it is now (its head): its lines and widgets follow; e.at(x, y, name), e.part, e.ground, e.spot — under Space;
  - e.point(ref) — where a point of the world is in its painting now ([x, y], its units; null if there is none): a person's ("david#hand_r", "rosa" — the head), an element's ("lamp", "door#knob"), or [across, distance, elevation] metres — a glow on someone's hand, a thought by a head, a thread from one to another (painted again as it moves); e.where(ref) — the same point in the world ({ across, distance, elevation }, metres; null if none): a torch carried in a hand, for the pools of its light painted on the walls and the floor;
  - e.debug(value, x?, y?) — a note shown only with ?debug (a module's poses and weights), at the point if given; e.warn(text) — wrong but not an error, said once in the scene's warnings (`no pose "wawe" — the poses: …`);
  - e.anim, e.kit.<module>, e.lib — shared code (below).
  Something that LIES FLAT is a plane — a floor, a pier's deck, a table top, a chessboard, a rug, a road, a pond, the sea near you:
  { "id", "name", "plane": true, "x": 0..1 (or "across": metres), "distance": metres (to its centre), "elevation": metres (0 on the ground, 0.75 a table top), "width": metres (across), "depth": metres (away from you), "rotation": degrees about the vertical (default 0), "tilt": degrees its far edge rises (− falls away), "drape": true (lies over the "relief", below), "walk": true (people stand and walk on it: a bridge, a deck, a landing), "reflect": true | { "strength": 0..1 (0.35), "fade": metres (4; 0 never), "blur": (0.05), "rough": 0..1 (0), "ripple": 0..1 (0) }, "lit": true, "color", "code" }
  Its code paints it seen FROM ABOVE, in metres, origin at its centre, x to the right, y TOWARD the viewer (a 8 m board spans x −4…4, y −4…4; its far edge is y −4). Paint it flat and true — squares square, planks straight; the engine lays it in perspective for wherever the viewer stands (never paint the perspective yourself). One plane may be as long as the place: a river or a road kilometres long is one plane — the engine paints it finer where it is seen close (don't cut it into pieces). "travel": { "across": key, "distance": key } — metres the viewer has gone over it (a train, a car): the plane stays, its painting passes under it, endless; paint it for e.area (the part of the painting being painted now, [left, top, right, bottom] metres) by where things lie — fields, roads, furrows that pass by and never repeat; it is not repainted as it moves. Things standing on a plane are normal elements at their own distance; people (elements with "person") stand on a plane that says "walk": true wherever it lies over them higher than the land — a bridge over a stream's bed, a deck, the top of a stack of logs (it may be "unseen": the floor of what a card paints). Its e.light glows where it lies. Whatever slopes is a plane with "tilt" (a roof's slope, a ramp, a stair; "rotation" 90 and "tilt": a deck's roll) — a card with "tilt" is what leans and swings (a lid, a board, a hatch). A plane shows its face to one before it: a roof's far slope, a slope above the eye seen from below, is its back — hidden by what holds it up. "reflect": a mirror — a polished floor, still water, a wet deck heeling over, a wet roof, a mirror on a wall ("tilt": 90, turned by "rotation" to face the room; its frame painted on the wall behind): all before its face (elements, their glows, halos, the sky, what shows through cut-out windows, the room behind you in a wall's mirror) is seen in it mirrored about its true plane, as bright as it is however the light lies on the mirror, following it as it turns; another mirror seen in it shows what it mirrors (once — each such pair costs the frame a pass), fading out over "fade" metres above it and blurring with height ("blur" per metre). What it mirrors keeps its own light: the sky and what glows as bright as they are, what is lit as the light falls on it there — a lake at dusk is as light as the sky over it, the dark shore darkens with the night. "rough": water under a breeze, wet stone — the mirror stretched down and up, and what shines drawing a long path of light on it — lights (e.light: give a sun or a moon painted in the sky one), what "glows", "celestials"; a bright sky does not (0.3: a lake, 0.6: the open sea). "ripple": small waves going over it break the mirror and its paths into moving glints (water). "lit": the scene's point lights (e.light, "lights" — give one a "reach" to reach the floor) lie on it as pools even where the scene is not lit: a lamp's spot, a fire's glow, light from a door.
A widget is a piece of interface over the scene — a sign over someone's head, a clock, a letter, a note, a map, a scoreboard, a panel with buttons — when the world needs one; most scenes need none:
  { "id", "name", "html": string,       // its HTML with <style> and <script> inside: HTML, CSS, JavaScript — anything a web page can do
    "width": px, "height": px,          // its size, in px of a 1080-px-tall screen (it is scaled with the screen)
    "x": 0..1, "y": 0..1,               // where it stands in the frame (interface: x 0.02 is the left edge on any screen) ...
    "follow": element id, "lift": metres, // ... or it hovers over that element (lift metres above its anchor; "id#name" — over a point it names) and moves with it as the viewer walks
    "anchor": "center"|"top"|"bottom"|"left"|"right"|"top-left"|…,  // which point of it sits there (default center; bottom when following)
    "interactive": boolean,             // takes clicks (default false: clicks go through to the scene)
    "at": seconds, "for": seconds }     // appears later / for a while, like captions
  Its markup and <style> live in their own shadow root (its CSS and the page's don't mix; the background is transparent). Its scripts run in the page, in order, with `root` — that shadow root: find its parts with root.getElementById / root.querySelector, not document — and `widget`, its element. Style it to belong to the scene (its palette and light), small and quiet.
State and mechanics — a scene can have its own, and needs nothing else to run them:
  "state" holds named values and where they start: the time of night, the dawn 0..1, a lamp lit, a ship's lights, where someone stands, what they are doing, what has happened. Each player has their own. Painting code reads the current values as e.state (e.state.dawn) and is repainted when they change — so the picture follows the state. The game played on the scene turns these values as its story goes (a girl who looks up, a door that opens, the light going out): give the scene the ones its story could need — who is there and what they can do, the light, what can happen — and paint every value well.
  A "script" — of the scene or of any element — is JS run with the scene, in its own thread (not the page: no document, no window; not painting). It gets `scene`: scene.state (current values), scene.get(key), scene.set(key, value, over?, ease?) (a number with `over` seconds moves there along an easing curve — 'smooth' by default; 'linear', 'in', 'out', 'inOut', 'back', 'spring', 'anticipate'), scene.cut({key: value, …}) (a new shot: the values at once, what came before forgotten — was(), the camera's glide, inertia: e.cut), scene.turn(key, degrees, over?, ease?) (an angle, the short way round), scene.path(keys, points, {speed | over, ease?}) (several numbers moved together through points as one movement — someone along a path, a cart on a road: [['cart_a', 'cart_d'], [[2, 8], [5, 12], [9, 13]]]; it slows nowhere but where its curve says; returns its seconds), scene.was(key, secondsAgo), scene.play(rows) (a timeline: rows [at, key, value, over?, ease?] or [at, fn], `at` the second from now or '+s' — s seconds after the row before it ends; [at, key, {turn: degrees}, …], [at, [keys], {path: points}, over, ease?], [at, 'cut', {values}]; returns when it ends), scene.anim, scene.kit.<module>, scene.lib, scene.every(seconds, fn), scene.after(seconds, fn), scene.time (seconds since the scene opened), scene.on('change', [key,] fn(value, old, key)) (once, as a value is set — with `over`, where it goes), scene.on('move', [key,] fn(value, last, key)) (each frame while a number moves — set with `over`, or along a path: what follows a moving value, e.g. places worked out from it), scene.on('load', fn(state)), scene.ground(across, distance) (the ground's height there, metres — "relief"), scene.prepare(values, seconds?) (the camera will be as `values` say in about `seconds`: what it will see made ready meanwhile — below, the camera), scene.tell(text, about?) (says something happened in the scene — a ship came round the cape, the candle burnt out; `about`: the element it concerns — so the game played on it can answer), scene.warn(text) (as e.warn). Scripts start each time the scene opens, with the state already restored: write them to go on from the state, not from the beginning (a clock: every 20 s add ten minutes to state.time).
  Scripts are the scene's mechanics only: they know nothing of the game played on it — no one is made to speak, nothing is decided for the player; clicks and talk belong to the game. Widgets use the global MooodState (.get, .set, .on, .all(), .states — the scene's "states"). Put the mechanics in scripts: a clock, a tide, someone walking to where the state says, a ship due at 00:50.
  Whoever can speak (a person, an animal, a talking thing) is an element of its own with a clear id and name, and marks its head with e.at() when it moves: its lines appear there.
  Describe the values in "states", so whatever turns them — the game, its agents, another artist — knows what they can be without reading your code: each key — "range": [min, max] (a number), or "values": [what it can be] ("shut", "ajar", "open"), or "type": "number" | "boolean" | "string"; "smooth": true — painted at every value between, moved with `over`; "means": what it shows ("0 — the door shut, 1 — wide open"). Where values start stays "state". A key set from outside that nothing in the scene knows or reads (its "state", scripts, painting) is said in a render's warnings — a mistyped key otherwise does nothing; with "states", a key they lack or a value outside them too, and an engine's key set to what it can't take (a look, fade, an insert, a light's "on" — 0…1) — so give every key of your own (the camera_… and fade are the engine's).
  Anything big is an element too: a range of hills far away is an element hundreds of metres off with a wide box; water reaching to the horizon is an element lying on the ground toward the horizon (or a very large plane); the wall of a room seen from inside is an element a few metres away with the window cut out ('evenodd') — what is painted farther shows through it with parallax. Elements are drawn far to near.

Light — the scene's light is state, and data its painting knows:
  - "looks": each key names a state value 0…1 turning the light toward that look — { "evening": {"ambient": 0.6, "ambientColor": "#ffb070", "tint": "#ff9050", "tintStrength": 0.15}, "night": {"ambient": 0.18, "ambientColor": "#5070c0", "saturation": 0.6, "haze": 0.5} }: scene.set('night', 1, 20) brings the night in over 20 s; looks apply in the order listed. Any field of "light" may be in a look, and "lights": { light id: how much of its strength } — {"morning": {…, "lights": {"moon": 0}}}: the moon's light goes out as the morning comes, by itself (with its shadows; "on" still multiplies); the sky element paints its own (let it read e.state.night too).
  - A lit scene — "ambient" in "light", or in a look as far as that look is in — lays its light on what is painted, by each thing's distance from each source: where none reaches a thing keeps "ambient" of its colour (times "ambientColor"); near a lamp it is lit full, crossing elements' boxes. What faces a way — planes (up, or down seen from below), and cards with "facing" — is lit by how it is turned to each source, lamps and those far off ("from": the sun on the faces turned to it, the shaded ones dim): a lamp's pool rounds over a side wall, the ceiling and the floor; a window's light falls on the walls by their turn. A card with no "facing" (a figure, a tree, a front painted flat) is rounded toward the eye: a lamp before it lights it full, one beside it half (a lamp by a door), one behind it little (whoever stands before the lamp is a silhouette); those far off evenly. The sky and "glows" elements keep their colours; e.light glows on top. Paint it in daylight colours and let the light make the night. Light bounces: what lies in a shadow or is turned from the light is filled by what is lit about it (light "bounce", 0.5) — a cloth hanging below a lamp on a table, a wall in the moon's shadow over bright snow; 0 for a stark, black-shadowed look. At once the 8 sources lighting most of what is seen from where the camera is are laid.
  - "lights": a point { "id", "across" (or "x"), "distance", "elevation" (metres), "place" (a lamp carried) — or "at": a person's point, in place of where ("keeper#hand_r": a lantern in their hand, going where the hand goes; not while they are away), "color", "strength" (1), "reach" (metres, 8), "on": state key (shines that much, 0…1), "flicker": 0…1, "glow": metres (a halo the engine draws) }; an element's own light taken over { "id", "of": "lamp" (its e.light; "lamp#wick" — one it names), and any of "color", "strength", "reach", "on", "flicker" } — it shines from wherever the element paints it (a lantern in a hand: a small glow, a long reach), its "on" putting out its glow too; or far off { "id", "from": [bearing, height] (degrees: 0 the far side, 90 the right, 180 behind the viewer; above the horizon) — "place": {"bearing": key, "height": key} moves it — or "from": "moon#disc", a point a sky element marks (e.at): it shines from wherever the moon is painted now, its shadows and edges following, "color", "strength", "on" } — the moon, the sun; with "through": [pane, …] — each a window element's id (its rectangle: a card, turned as it stands, a pane of glass, a plane) or a flat polygon of [across, elevation, distance] points, metres — it comes in only through them, its edge "soft" (metres, 0.3): what is past them (in the room — "inside" — or beyond their plane) it lights only where the way to it goes through one — the sun's patch on the floor, cast along the beam and up a wall, as bright as outside; its shafts across a gallery, lighting who stands in them — what is before them all (the yard the window looks out on) as any light far off. People, e.lights, shadows (the sun's shadow inside falls only in its patch), and a scene the engine lights on its surfaces too. Every e.light() is a source too; all are what e.lights() reports and shadows are cast from.
  - Inside and outside: a room, a carriage, a cabin is darker than the world beyond its window. Mark what is in it "inside": true (its walls, floor, things, people) and give "light" an "inside": 0…1 — how much of the light outside reaches in (0.3: a room by day as dim against the window as it should be; night outside, night in; in a look too). The light coming in at a window is a light with "daylight": true, or how strong (1) — its colour and strength are the outside's now (day, dawn, moonlight), and it lights only what is inside. Give it "of": the window element (its frame, or its pane of glass — a card, turned as it stands, or a plane) and it comes in at all of the window: into the room only, the way the window's face looks, strongest straight before it and less aslant; the wall the window is in and what is outside get none of it, and the shadows it throws are as soft as the window is big (a sill or a table by the window shades the floor, not the wall). Without "of" it is a point where you put it. The sun and the moon come in as the "inside" share, unless they come in "through" the windows (above): then only there — no share of them anywhere else inside, and a wall is not lit from behind. Lamps light both.
  - "shadow": the element — or a plane: a table top, a roof's slope, tilted or level — casts its own painting, black, where the light throws it — onto "ground" (height 0), a plane (a floor, a table top) or an upright element (a wall: only where it is painted), wherever its ray meets each of them (the floor and the wall meet without a gap; what stands before it there hides it) — on "ground" the land as it rises and falls (a footbridge's shadow goes down into the riverbed and up its banks): a shadow runs along the floor and climbs the wall. The shadows of one light are one shadow, whoever casts them — a hut's walls and roof slopes are not darker where they overlap; two lights, two shadows. "light": a source's id (default: each that lights it noticeably — up to three, each shadow as dark as its light's share there: a lamp on each side, two shadows); "soft": the light's size, metres (0.15: blurring away from the contact); "strength" (0.5): how dark in full light. Keep the lamp outside the casting element (the lights an element paints, and those of what it stands on — a stove's fire — cast none of its shadows). Parts (e.part) cast from where each stands. What is out of the frame casts still — the wall at your back, looking round.
  - "translucent": what is thin lets the light behind it through — lit from behind it glows its own colour that much (a sail against the low sun, leaves, a paper lantern, a curtain at a window), and its shadow lets as much through. A wall painted flat is a card as a sail is; only you know which is thin.
Moving things — a scene can be a short film, the situation unfolding before the eyes:
  A film is the scene's state moved along a timeline: semantic values (who is where, what they are doing, the light, what has happened) that the elements paint at every value, and the scene's script that, each time the scene opens, sets them to where the film starts and plays them (scene.play). The values stay the scene's parameters: whatever is played on it can move them too.
  An element that walks off into the distance or comes near has "place": its across, distance, elevation (or x) are the names of state values (metres) — the engine puts it there every moment: its size, its haze, and what it is drawn in front of or behind follow; on a "relief", over the land — up a bank, down to the water. Its code paints it at its anchor as usual. "facing" and "tilt" too (degrees; a plane's "tilt" too: a deck rolling): a door or a window leaf opens — the card turns about its anchor, so paint it from its hinge (x 0 → its width; a leaf hinged on the right: x −width → 0): "facing": 180, "place": {"facing": "door"}, door 180 shut → 262 open into the room (the free edge comes toward the viewer: + for a card painted to the right of its hinge, − for one painted to the left); move it with scene.set(…, over) or scene.turn. Two leaves: two keys moved together.
  "on": "house" — it stands on another element and goes and turns with it: its "across", "distance", "elevation" are metres from that one's anchor along its own axes, as if it faced the start (across to its right, up, away behind its face; on a plane: across it, up from its face, toward its far edge), and its "facing", "tilt" turn within that one's. A thing built of cards is so assembled on an unseen anchor and turned as a whole by one number:
  {"id": "house", "unseen": true, "across": -6, "distance": 12, "facing": 200}, {"id": "front", "on": "house", "facing": 180, …}, {"id": "side", "on": "house", "across": 3, "facing": 90, …}, {"id": "roof_front", "plane": true, "on": "house", "elevation": 3.8, "distance": 1.25, "tilt": 32, …}
  — "place": {"facing": "house_turn"} on the anchor turns it all; a ship heels the same way ("tilt"). A chain carries along; what stands on something is not set on the relief. Its shadows, lights ("of"), points, speech follow. Not on the sky, the ground or an insert.
  The camera a film moves, through state values:
  - camera_target: an element's id ("id#name" — a point it names) — an operator frames it and keeps it framed as it moves, room ahead the way it goes, setting off and settling gently, easing from one target to the next; null — back to the scene's own camera. Its point is its e.at (a head), else its box's middle. It may be off the frame (the operator turns to it) or "unseen" (a point to look at: between two people). camera_shot: "wide" (a third of the frame), "full" (default), "medium" (waist up), "close" (head and shoulders), or how many times the frame's height it is tall; camera_frame: where its point goes, [x, y] fractions of the frame (x alone: across); camera_glide: seconds to get there (1.5; 0 — at once). Ahead the operator dollies and slides; looking around it turns and comes as near as the shot needs. Looking around, it never shoots through what stands between the lens and the target, nor stands inside it: as a shot begins, if a person or something truly painted (not a veil, glass, a glow) hides most of the target, it goes round to the nearest bearing that sees it, then nearer, within the scene's area, and keeps that for the shot — a shot moved by camera_x, camera_z, camera_h or camera_yaw is taken as it says. The viewer's own moves go on top — a look aside, easing back once they let go, never nearer than half the way to the target; a platformer's camera rides with its hero instead.
  - camera_x (metres right), camera_h (metres up — the target stays framed), camera_z (metres ahead — a dolly in, with all the scene's depth: everything stands at its own distance, however far — a flight kilometres along passes what stands on the way), camera_look (screen heights the gaze is lowered): added on top of the framing or the scene's camera. They start at 0.
  - The camera turned, degrees, on top of all that: camera_pitch (up; −75…75 — the lens shifted, as camera_look: what stands stays upright), camera_yaw (to the right, all the way round in any camera: a flight back the way it came looks ahead with 180 — looking ahead (walk, picture…) what stands in the world is seen truly from any side; what is painted on the stage from its front — the sky, the landscape layers — is a backdrop round the start at its bearing, as the sky looking around: turned, it goes aside and behind; behind it nothing is painted, the sky's edges carry on there, its right passing into its left — a scene to be seen all round paints its sky and its far land for around/roam), camera_roll (the camera tipped to the right, the horizon rising to the right: a banked turn, a Dutch angle — the whole picture turns, inserts too, and comes a little closer to fill its corners: 5° ≈ 15%). Move them with `over` like any number.
  - fade 0…1 — the frame fades to fade_color (black by default).
  A cut is scene.cut({camera_target: "keeper", camera_shot: "close", …}) — the new shot at once, the viewer's moves undone. The camera put elsewhere at once — a cut, or a camera value set without `over` — is a new shot: the engine makes all of it before it is shown (the frame before it held meanwhile, at most half a second); so the camera following something moves with `over` or along a path, not by values set at once frame after frame. scene.play makes its camera's new shots ready ahead; a script that knows where the camera will be says so: scene.prepare({camera_x: 2, camera_z: 7.7, camera_yaw: -8}, seconds) — that shot is then shown at once, made. Moving past near things is fine: an element fades only in the last 60…20 cm before the eye (a curtain of leaves walked through); one beside the way slides out of the frame whole first.
  An insert — a shot of its own over the scene, fixed to the frame whatever the camera does (a hand close up, a letter, a face): an element with "insert": a state key opening it, 0 (closed — not painted) … 1 (open), set with `over`. Its code paints in stage heights like the sky (x 0..e.aspect, y 0..1; paint its own background). It is seen through an iris: "iris": [x, y, rx, ry] — the window fully open, an oval (centre and radii, stage heights), opening from its middle; without it, from the middle of the frame to all of it. The scene goes on under it; closing it is the way back. No haze, no camera, no depth; it is over everything — "behind", "inFront" and "clip" neither name it nor are its.
  e.anim (scene.anim; `anim` in a module's and the lib's code): ease.{smooth, linear, in, out, inOut, back, spring, anticipate}(u), easeOf(name), clamp, mix(a, b, u), span(v, a, b) (how far v is from a to b, 0…1), turn(a, b, u) (radians, the short way), hash(n, seed) (a steady random 0…1 for n — unlike e.rnd() it doesn't shift when some calls are skipped), noise(x, seed) and drift(x, seed) (smooth −1…1 that never repeats — breath, sway, a restless hand), joint(x0, y0, x1, y1, a, b, bend) (a two-bone limb: where the elbow or knee is when the hand or foot is set at x1, y1), blend([[pose, weight], …]) (poses — objects of numbers — mixed).
  Shared code: "lib" is the body of function (anim, kit) returning what the scene's elements share (a figure drawn by several of them, a path they walk); "modules" lists the world's modules the scene uses — code all the world's scenes share (its people, its animals, its things), each with notes on what it offers — and they come as e.kit.<name> (scene.kit.<name>; kit.<name> in the lib). A scene gets the modules as its world has them: when a module gets better, so does every scene that uses it. Use the world's modules for the world's people, so they are the same people in every scene. Someone who moves as a person does — walks, sits, turns, gestures — may be an element with "person": real human motion, drawn in 3D in a style and lit by the scene, what they do in the state (people.md says how). A module says with e.warn what it is given and does not know (a pose, a figure) and writes with e.debug what it does (its poses and weights). The lib and a module may offer beforeFrame (below).
  Painting and beforeFrame — two functions, each with its own job:
  - Painting — an element's code, and the lib's or a module's code it calls — paints what is now from what it is given: e.t, e.state, e.was, e.speed, and what beforeFrame keeps. It keeps nothing itself: no variable (the lib's, a module's, its own) is written as it paints to be read by a later painting. A moment is painted the same whether the frames before it were painted or not — a render of a film's 80th second, a game catching up, paint only the frames they show.
  - beforeFrame({ t, dt, state, was, speed, cut, at }) — offered by the lib or a module — runs once every frame before anything is painted, whether the frame is drawn or not, and once as the scene is shown. Memory lives there: what goes on from frame to frame — a spring, a step, a pace or a phase added up by dt, a recorded action's progress, a lag — is worked out there (afresh after a cut: cut). It paints nothing. Its t, state, was, speed are an element's e's, so one function of the lib works a figure out from either: beforeFrame moves it with that function, its element paints it from the same — and reads e.t, since what is kept changes from frame to frame (a module's people do: its notes say how). at(id, x, y, name?) marks element id's point (as its e.at would: metres from its anchor) this frame — the camera and the lines follow it on frames nobody sees too.
  - Which goes where: what follows from now alone (e.t, the state, was, speed) — painting; what depends on how the frames before went (added up, sprung, remembered) — beforeFrame. A point that moves with what beforeFrame keeps, or one the camera follows as it moves (camera.follow, camera_target), is marked by beforeFrame's at; one that stays (a window), by the painting's e.at.
  For example, a lantern swinging on a spring, pushed by the wind:
    lib: let a = 0, v = 0; return { beforeFrame({ dt, state }) { v += (-9 * a - 0.6 * v + (state.wind || 0)) * dt; a += v * dt; }, swing(e) { e.t; return a; } };  // (swing reads e.t: what reads it is repainted every frame)
    lantern: g.rotate(e.lib.swing(e)); …
  — not `a += v * dt` in the lantern's painting: a render that skips frames would find the lantern elsewhere.
  The craft of motion — what makes it feel alive and human, not mechanical:
  1. Nothing moves at constant speed: everything eases in and out; a fall gathers speed (in), a hand settles (out), a look turns past and back (back). Linear only for what is driven: a cart, a current.
  2. Anticipation: before an action a small move the other way — crouch before the jump, lean back before the throw, a breath before the word.
  3. Follow-through and overlap: parts don't stop together. The head leads, the body follows, the arms and the coat, the hair, the reins follow later and settle with a sway (e.was). A turn begins with the eyes and the head.
  4. Arcs: hands, heads, feet travel on curves, not straight lines.
  5. Weight: the body dips as the foot takes it, rises as it passes; a standing body rests on one leg and shifts now and then; the heavier, the slower the start and the stop. The step's phase follows the way gone, so feet never slide.
  6. Strong poses and holds: one clear pose, a pause in it (breathing, a small shift — never frozen, never fidgeting), then a quick move to the next. Every key pose must read as a silhouette; if it doesn't, motion won't save it. Give the eye 1.5–3 s to read each action, and the others' reactions after it.
  7. Crowds are never in step: each person a little late or early, a little faster or slower (anim.hash per person).
  8. Fewer, better movements: two slow good ones beat ten busy ones. Small figures forgive more; a big figure must move well.
  9. Bodies are shapes, not sticks on hinges: tapering limbs, joints hidden by clothes — coats, skirts, sleeves, hats carry the motion.
  10. Contact with the world: a shadow under the feet, dust where they land, rings where they enter water.
  11. Everything moves a little, and slowly — speed sets the mood more than colour; several sines of e.t at non-multiple frequencies show no cycle; e.rnd is seeded, the scene the same each time it opens.

Space — what is in front of what, the land, parts, points:
  Elements are drawn far to near; at one distance, the later in "objects" in front — and what is nearly opaque hides what stands truly behind it, point by point (a fence aslant and someone by it, a table and the wall): turned cards and planes as they lie, a card facing the eye at its distance (what it paints below its foot lies on the ground). When that is not what is meant, say so instead of tuning distances (4.68 against 4.95): "behind": ["table"] — drawn behind those, "inFront": ["rock"] — in front of them.
  "clip": {"inside": ["doorway"]} — seen only where those elements are painted now (as they stand in the frame): a figure walking in through a doorway, a face behind a pane, a reflection in a puddle; {"outside": ["table_top"]} — only where they are not: a body below a table top, legs under water. A shape painted only for this is an element with "unseen": true: placed and painted like any other, never shown, never picked.
  "glass": a pane of glass — a window at night, a train's window, a shop window: it paints only where the glass is (the opening, plain fill; frames and bars are another element over it — "behind": ["wall"]), and is not shown itself: in it, faintly, what is on the viewer's side of it is seen mirrored — the room, lit as it is, its lamps, even one over the viewer's head out of the frame — smaller and farther, as behind the glass, blurring the farther from the glass ("blur" per metre). It shows where it is dark beyond the glass and light before it: at night; by day hardly (a lit scene: as its ambient light leaves the street dark; else on what is dark behind). With "facing" it lies as that turns it; else across the gaze. Only what stands on the viewer's side, not cut by others ("clip").
  "relief" — the land: the body of function (across, distance, anim, lib) returning the ground's height in metres there (across: right of the start's line of sight; distance: ahead). A bank rising to 1.4 m at 10 m and down to a stream at 14 m: "return 1.4 * anim.span(distance, 6, 10) - 1.8 * anim.span(distance, 11, 14)". Keep it 0 where the viewer starts. Then:
  - what is placed by its "distance" stands on it (its elevation over the ground there), and one moving ("place") goes over it: down the bank to the water is a walk, not a slide down the screen;
  - a card that is a picture of the land itself (a bank painted side-on, the stones and sand on it, drawn in the land's own metres) says "onLand": false — it stands at its elevation, not lifted onto the relief it draws;
  - a plane with "drape": true lies on it like a cloth: paint the land as such planes (a field, a bank, a road), its slopes true from anywhere — laid as finely as the land bends (a narrow bed, a steep bank, a crest keep their shape) and as it is seen — what is sheer, steeper than 80° (where the relief jumps: a cliff's edge returning one height on one side and another on the other), the land does not draw: a card for the cliff's face stands on that line, its painting sharp close up as any plane's; lit as each slope faces the light (a bank toward a low sun bright, the far one dark), shadows lying along the slope they fall on; other planes stay flat (water, a table, a floor) — keep the land under water below the water's plane;
  - a rise of the draped land hides what is behind it, cut along the land as drawn: riders going over a crest sink behind it — nothing to paint or duplicate;
  - the viewer's eyes stay 1.7 m over the ground; code reads it — e.ground(across, distance), e.spot ({ across, distance, elevation, ground }, metres: where it stands), scene.ground, the game's: one land for everyone.
  Parts: one element standing at several depths — a fence along a road, a crowd: e.part(dx, dz, g => { … }, box) paints a part dx metres right and dz farther than its anchor (on the ground there; on an element `on` another — along what carries it, at its own height: grass on a raft, on a deck; of a card turned by "facing"/"tilt" — along its right and behind its face, lying in its plane, turned with it: the houses of a row, steps one behind another, dormers on a roof's slope, a sail's cloths on a mast that turns with its ship — each lit as the card is, casting its own shape), in metres from its own foot (box around it, [left, top, right, bottom]; the element's without one), drawn at its own distance — what stands between is drawn between, a rise hides each on its own; close up each part is painted again as finely as it is seen (as a card turned by "facing" is). Call it each time the code paints.
  Points: e.at(x, y, 'name') names a point as painted now — a window, a head, a boat on the water — for the game (its lines, marks, a mini-game's target: where('farm#window')) and the camera (camera_target: "farm#window"), instead of numbers copied out of the code. Mark them in the painting (a part too); one no longer marked is gone — one that moves with what beforeFrame keeps, or that the camera follows as it moves, by beforeFrame's at (Painting and beforeFrame, above). Name every point a game could point at.

A platformer ("camera": {"mode": "platform", "hero": id, "jump": metres}): the viewer runs and jumps as the hero (keys or touch), the camera riding along. "solid": true elements are what it stands on and bumps into — the box across their "box", from their "elevation" up their "height" (the ground, steps, ledges, crates: paint them to look like that box). Lay the level out along "across" at one "distance", scenery nearer and farther. The hero is painted once, facing right, at the start: the engine moves it and turns it when it runs left; its code reads e.hero ({ vx, vy m/s, ground }) for its legs and arms; "width" (0.6 m) is how wide it bumps, "jump" how high (2.2 m). Scripts read scene.hero() ({ across, elevation, ground }): coins, doors, someone who speaks when it comes near.

Checking your work — what is on screen counts, not what the code means (a browser without WebGL2 is told it cannot show the scene). ?debug in the scene's address draws over the frame each element's box and id, anchor, e.at points, parts, paint cost and e.debug notes, and the scene's errors and warnings (?debug=keeper,boy — only those); key P shows what each painting costs a frame. render_scene (moood's MCP) draws any second of a film — a sheet, a film, a pack of frames.

"notes" are yours to keep, if you want them: whatever would help whoever changes this scene next understand it — how it is built, what its parts and values do, what is tricky in its code or easy to break, what you meant and planned. Keep them true as the scene changes.

CRAFT — how to make a scene alive and atmospheric (apply with judgement; most scenes benefit). Respect the person's description literally (time of day, weather, season, objects, mood); invent tasteful details only where they left gaps; compose for the starting view (the hero shot).
1. One feeling first. Name it in one word (loneliness, silence, waiting, joy). Test every decision: does it strengthen the feeling or distract? Silence = few elements, slow motion, low contrast, a lot of emptiness.
2. Composition — emptiness tells the story. The figure is small and off-centre; most of the frame is the space around it. The horizon is not in the middle: lower it so the sky presses down, or raise it so the water pulls in. One leading line (a pier, a path, a window edge) leads the eye from the frame's edge to the hero. The light source and the hero are near each other but not together — the distance between them is part of the story.
3. Light and colour. A narrow palette of 3–4 close tones plus one warm source; everything else cooler and darker. Paint light with soft radial gradients — hard circles and spots look digital. Silhouettes very dark but never pure black: a shade of the palette keeps the picture whole. One colour accent, muted and small (a scarf).
4. The character: posture instead of a face. No face needed — a hunch, dangling legs, hugged knees read better than any expression. Build the figure from a few simple shapes; test: it must read as a black blot. Micro-motion is a must: breathing, legs swinging out of step with each other, cloth stirring — amplitude almost invisible, but without it the picture is dead.
5. Water and air — the main sources of poetry. A reflection is the same scene mirrored vertically, cut at the water line, at low opacity. The water surface is thin horizontal strokes — short and dense near the horizon, long and sparse toward the viewer: that makes the perspective. The sun's path is shimmering horizontal dabs, not a gradient. Rings on water are flattened ellipses, flatter the farther away; they spread slowly and fade. Air: fog bands at the horizon, a few dust motes.
6. Post: vignette gathers the eye to the centre; film grain changing every frame removes sterility (light.vignette, light.grain).
7. Text: one short line at a time, fading in (captions with "at"/"for"). A concrete detail ("counts the raindrops, loses count") is stronger than a named feeling ("she is sad").
8. Paint back to front: sky → light → far shore → water → fog → reflection → ripples → foreground → hero → effects. Avoid: saturated colours, fast motion, detailed faces, objects added "to fill", clip-art cuteness, perfectly even repeating animations.


Translations: a scene is written in English; its translation into each other language its world is in lies beside it — the scene's lang/<language>.json ({"strings": [entries]}; moood-check --write — npm @moood/check — lays it out and says what is missing): an entry for every text a person reads or hears, once: the title, the caption, the captions' texts, the texts of the widgets' markup (between tags, and their title/alt/placeholder), every tr('…') of its code, every line said (scene.say('id', '…'), s.person('id').say('…') — with "who": the id). An entry is { "text": the English exactly as written, "translation": it in the language }; a tr.n's — { "text": its one form, "plural": its other form, "translation": { "one": …, "few": …, "many": …, "other": … } as the language counts (a {n} in each) }; a tr.c's has "context": its first argument. {names} stay as they are. Not the element names, `means`, notes or music: they are yours, in English. A text changed or new — its translations with it, in the same turn; a text gone — its entries gone. Translate as a writer would, in the place's own voice, not word for word.
